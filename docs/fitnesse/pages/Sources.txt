!2 A — Schema & TrackingId Location

!3 Q1 — Where does TrackingId live?
 * '''Date''': 2026-04-16
 * '''Scope''': tbl_email, tbl_email_links, tbl_analytics_link, tbl_email_receiver_status — search for columns tracking/camms/cpid/cplan.
 * '''Finding''': TrackingId exists '''only''' on imep_bronze.tbl_email (mailing level), not on engagement tables. Example: ABCDE-0000123-240709-0000045-EMI. Cross-channel is a dimension, not a fact key.

!3 Q1b — Evaluate iMEP Gold layer
 * '''Date''': 2026-04-16
 * '''Scope''': Full schema + sample on imep_gold.tbl_pbi_platform_mailings and tbl_pbi_platform_events.
 * '''Finding''': Gold is mailing/event master with content & registration metrics — '''not''' a Send/Open/Click aggregate (Tier 2 carries those). Sentinel value 2124 for open-ended events.

!3 Q2 — Full core schemas
 * '''Date''': 2026-04-16
 * '''Scope''': DESCRIBE for TBL_EMAIL, TBL_EMAIL_RECEIVER_STATUS, TBL_ANALYTICS_LINK, TBL_EMAIL_LINKS with types + sample.
 * '''Finding''': 111 columns total, all nullable. tbl_email 54 cols, tbl_email_receiver_status carries LogStatus/TNumber/EmailLanguage, tbl_analytics_link 22 cols incl. Agent/LinkTypeEnum/EmailReceiverStatusId, tbl_email_links 10 cols (lean).

!3 Q3 — HR bridge TNumber ↔ GPN (first round)
 * '''Date''': 2026-04-16
 * '''Scope''': tbl_hr_employee, tbl_hr_user — identifier column inventory.
 * '''Finding''': '''Hypothesis falsified''' — no visible GPN column. T_NUMBER (lowercase) and __ORG__Id (uppercase) are both T-numbers. Search was too narrow → opens Q3a/Q3b.

!3 Q3a — What IS the GPN in AppInsights?
 * '''Date''': 2026-04-17
 * '''Scope''': match 10 GPN sample values from AppInsights pageViews against HR columns (with string transformations).
 * '''Finding''': Superseded by Q3b — GPN is WORKER_ID in HR, no string transformation needed.

!3 Q3b — Extended HR search for the GPN column
 * '''Date''': 2026-04-17
 * '''Scope''': Three-step deep search across all HR tables — name tokens, 8-digit pattern counts, schema scan.
 * '''Finding''': imep_bronze.tbl_hr_employee.WORKER_ID '''is''' the GPN. The same table carries T_NUMBER too. Bridge = simple LEFT JOIN, no external source.

!2 B — Engagement Events & Coverage

!3 Q16 — iMEP Gold inventory + attribution lag
 * '''Date''': 2026-04-18
 * '''Scope''': Which Gold tables carry UniqueOpens/UniqueClicks per Mailing × Region/Division. Raw inventory of the 5-tier architecture.
 * '''Finding''': Global open/click rates computable (clicks far rarer than opens; rates differ markedly by region). NULL region for the majority of recipients on Tier-3 aggregates → data quality blocker. Tier-3 pivot of tbl_pbi_kpi documented.

!3 Q17 — SharePoint Gold + CPLAN inventory
 * '''Date''': 2026-04-18
 * '''Scope''': Which tables in sharepoint_gold, sharepoint_clicks_gold, sharepoint_cplan are accessible; which carry PageView/CTA metrics.
 * '''Finding''': sharepoint_gold (20 tables, hundreds of millions of rows) + sharepoint_clicks_gold (CTA) + sharepoint_cplan (Clusters/Packs/Activities) are all in Databricks. pbi_gold (60 tables) '''not''' accessible.

!3 Q21 — iMEP Gold Tier-3 schemas
 * '''Date''': 2026-04-19
 * '''Scope''': DESCRIBE + sample for tbl_pbi_mailings_region, _division, tbl_pbi_kpi, tbl_pbi_platform_mailings — join keys and data types.
 * '''Finding''': Join key MailingId is lowercase mailingid on the engagement side! Match rates vary widely by table (not all mailings have Tier-3 entries). UniqueOpens NULL for a substantial minority of rows, UniqueClicks NULL for the majority — '''semantic NULLs''', not defects. tbl_pbi_kpi is pivoted (measure + MailingReceiverStatus).

!3 Q22 — SharePoint Gold metric schemas

!2 C — TrackingId Format & Match Strategy

!3 Q23 — TrackingId format consistency iMEP ↔ SharePoint
 * '''Date''': 2026-04-20
 * '''Scope''': Structural comparison tbl_email.TrackingId ↔ sharepoint_bronze.pages.__ORG__GICTrackingID — length, case, segments, value overlap.
 * '''Finding''': Format identical (32-char 5-seg UPPER clean) '''but''' values nearly disjoint (only a handful of values appear on both sides). SEG5 = channel (iMEP: EMI/NLI/TWE; SharePoint: IAN/ITS/OPN/ANC). '''Business-refined 2026-04-20: Cross-channel match is Pack-Level (SEG1-2) ONLY''' — SEG1-4 also fails because email and page of the same pack have different dates (SEG3) and activity sequences (SEG4).

!3 Q24 — TrackingId volume & adoption
 * '''Date''': 2026-04-20
 * '''Scope''': How many mailings actually have a TrackingId? Adoption over time + channel distribution.
 * '''Finding''': Only a small minority of mailings (low single-digit percent) have TrackingId. Adoption starts in 2024 and ramps up steeply (2025 several times 2024, 2026 YTD on track to exceed 2025). The large majority are EMI. '''Hundreds of EMI rows → slightly fewer distinct TIDs → a few dozen distinct Pack IDs (SEG1-2)'''. Dashboard universe = a few dozen packs, default time window from 2025.

!3 Q25 — __ORG__GICTrackingID distribution in pages
 * '''Date''': 2026-04-20
 * '''Scope''': Which SharePoint sites have tracking coverage, over which time spans, with which URL mapping?
 * '''Finding''': Virtually all tracked pages on '''one single site''' ("News and events", several dozen packs). Coverage rollout Sep 2024 (jump from near zero to a substantial share), peak March 2026, never 80%. 1:1 URL↔TID mapping. Dashboard → restrict to News-and-events + floor 2024-09-01.

!2 D — Pipeline Lineage without Unity Catalog

!3 Q26 — Silver existence via schema naming
 * '''Date''': 2026-04-20
 * '''Scope''': SHOW SCHEMAS scan — which schemas end in _silver, which in _bronze / _gold?
 * '''Finding''': 17 _silver schemas exist. '''SharePoint uses the full Bronze→Silver→Gold''' (sharepoint_silver, webpagevisited with hundreds of millions of rows). '''imep_silver exists only for events''', email engagement skips Silver → imep_gold.final (hundreds of millions of rows) is the direct consumption endpoint. Medallion asymmetric. Stop planning silver.fact_email.

!3 Q27 — Join graph via column fingerprint
 * '''Date''': 2026-04-20
 * '''Scope''': Scan all table schemas × 8 schemas for EmailId/TrackingId/TNumber/GPN columns; reconstruct the join graph.
 * '''Finding''': 93 tables / 8 schemas mapped. Two full-key hubs: tbl_analytics_link + tbl_email_receiver_status (hundreds of millions of rows each). EmailId in 12 tables, TNumber in only 2 (→ person analytics = email-grain only), TrackingId in exactly 4 and '''never co-occurring with EmailId''' → TrackingId is dimension, not fact. Cross-channel = TrackingId ↔ GICTrackingID via pages, '''not''' via engagement. New schema page_metadata_bronze discovered.

!3 Q28 — Pipeline hints from Delta History
 * '''Date''': 2026-04-20
 * '''Scope''': DESCRIBE HISTORY on the largest tables — write operations, Service Principal, operation types (MERGE/CTAS/Append).
 * '''Finding''': Unified MERGE → OPTIMIZE → VACUUM rhythm, 7-day retention. iMEP Bronze MERGE Upsert (tbl_analytics_link truly incremental, thousands/run; tbl_email / tbl_email_receiver_status full-replace, up to tens of millions/run). SharePoint Bronze: pages MERGE snapshot, pageviews Append WRITE (a handful of bursts = API pagination). iMEP Gold Full Rebuild — the final table (hundreds of millions of rows) is completely rewritten = biggest compute cost. All writes via Service Principal (identity not recorded here). '''Scope limit''': concrete UTC refresh slots only visible in History, no complete scheduler view.

!3 Q29 — Gold tier structure from table shape
 * '''Date''': 2026-04-20
 * '''Scope''': Scan 52 Gold tables (iMEP + SharePoint) for row count, distinct-key count, column count; derive 4-tier hierarchy.
 * '''Finding''': Strict 4-tier hierarchy. '''Tier 0''' = atomic fact (imep_gold.final, hundreds of millions of rows, grain mailing × recipient × event × hour; sharepoint_gold.pbi_db_interactions_metrics, tens of millions). '''Tier 1''' = timespan × dim (15 tables). '''Tier 2''' = per-mailing summaries (incl. anomaly: engagement mixes emails+events, with more distinct mailingIds than the mailing master has rows). '''Tier 3''' = platform & reference dims (tbl_pbi_platform_mailings, tens of thousands of rows, hundreds of distinct TrackingIds). Cross-system bridge = dimensional via tbl_pbi_platform_mailings.TrackingId → pages → marketingPageId. SharePoint Gold has video sub-domain (3 tables, managed Declarative Pipeline).

!3 Q30 — Table properties & storage location
 * '''Date''': 2026-04-20
 * '''Scope''': DESCRIBE DETAIL / SHOW CREATE TABLE on 114 tables — ADLS paths, partitioning, formats, pipeline owners.
 * '''Finding''': 114 External Delta tables across 3 ADLS accounts (iMEP-bronze, SP-bronze, shared Gold). '''Gold is co-located''' → cross-channel joins possible inside Fabric/Spark. '''111/114 via notebook-CTAS''', only 3 video tables via Declarative Pipeline. '''⚠️ Zero partitioning on all tables''' — biggest structural performance gap; impacts final (hundreds of millions of rows) + interactions_metrics (tens of millions). SharePoint Bronze has ad-hoc historical snapshots (pageviews_09_27_2023 etc.). iMEP Gold paths: /final root + /tbl_pbi/* + outlier /imep/tbl_active_employee_month.
