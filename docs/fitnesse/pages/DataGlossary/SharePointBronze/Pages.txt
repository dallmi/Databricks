!1 Pages ('''sharepoint_bronze.pages''')

'''The cross-channel bridge.''' Page inventory with __ORG__GICTrackingID — '''the only place''' where SharePoint-side interactions can be attributed to a Pack. Tens of thousands of rows, but only '''a small minority (low single-digit percent) have __ORG__GICTrackingID populated'''. The most critical coverage blocker in the entire cross-channel model.

!2 Meta
| '''Layer'''          | Bronze |
| '''Source system'''  | SharePoint -> Change Data Capture (CDC) or Snapshot -> Delta Bronze |
| '''Grain'''          | 1 row per SharePoint page (snapshot) |
| '''Primary key'''    | pageUUID (GUID) |
| '''Cross-channel key''' | __ORG__GICTrackingID — '''only a small minority populated''' ⚠️ |
| '''Write pattern''' | MERGE daily snapshot replace (Service Principal) |
| '''Rows'''           | '''Tens of thousands''' (timespan 1900 - Apr 2026) |
| '''Coverage'''       | A small minority of pages (low single-digit percent) have TrackingID -> '''article pages only (News/Events)''' |

!2 Primary Joins

!3 Join to pbi_db_interactions_metrics (1:N) — Standard cross-channel path

{{{
SELECT p.__ORG__GICTrackingID, p.PageURL, p.__ORG__ArticleDate,
       SUM(m.views)  AS total_views,
       SUM(m.visits) AS total_visits,
       COUNT(DISTINCT m.viewingcontactid) AS unique_viewers
FROM   sharepoint_bronze.pages p
JOIN   sharepoint_gold.pbi_db_interactions_metrics m ON m.marketingPageId = p.pageUUID
WHERE  p.__ORG__GICTrackingID IS NOT NULL
  AND  m.visitdatekey   >= '20250101'
GROUP BY p.__ORG__GICTrackingID, p.PageURL, p.__ORG__ArticleDate
}}}

!3 Join to sites (N:1) — Site context

{{{
SELECT p.*, s.SiteName, s.SiteUrl
FROM   sharepoint_bronze.pages p
LEFT JOIN sharepoint_bronze.sites s ON s.SiteId = p.SiteId
}}}

!3 iMEP cross-channel link (Pack / SEG1-2)

{{{
-- Pack-level link: tbl_email × pages via Pack-Level (SEG1-2)
WITH email_packs AS (
  SELECT DISTINCT
         array_join(slice(split(UPPER(TrackingId), '-'), 1, 4), '-') AS seg1_4,
         TrackingId AS email_tid
  FROM   imep_bronze.tbl_email
  WHERE  TrackingId IS NOT NULL
),
page_packs AS (
  SELECT DISTINCT
         array_join(slice(split(UPPER(__ORG__GICTrackingID), '-'), 1, 4), '-') AS seg1_4,
         __ORG__GICTrackingID AS page_tid
  FROM   sharepoint_bronze.pages
  WHERE  __ORG__GICTrackingID IS NOT NULL
)
SELECT e.email_tid, p.page_tid, e.seg1_4 AS common_activity
FROM   email_packs e
JOIN   page_packs  p ON p.seg1_4 = e.seg1_4
}}}

!2 Quality Caveats — Critical

!3 ⚠️ Low-coverage blocker

Only '''a small minority of pages (low single-digit percent)''' have __ORG__GICTrackingID. Consequence:
 * Only a low single-digit percentage of the tens of millions of SharePoint interaction rows are Pack-attributable
 * The vast remainder = "untracked intranet activity" (internal tools, settings, collaboration pages etc.)
 * '''The dashboard must make this explicit''' — either (a) show only the small tracked subset labelled "Article Pages only", or (b) two separate sections (attributed vs. unattributed)

!3 Site concentration

'''Almost all tracked pages''' live on '''a single site''': "News and events".
 * Dashboard default '''should''' be restricted to this site
 * Coverage reality check: only several dozen Pack IDs (SEG1-2) accessible to this dashboard

!3 Coverage rollout

 * Start of TID population: September 2024 (only a minority of new pages covered)
 * Peak so far: March 2026 (a clear majority of new pages)
 * '''Never reached full coverage''' — even "current" pages have a substantial share of missing TIDs

Default time filter: WHERE __ORG__ArticleDate >= '2024-09-01'.

!3 Format inconsistencies

 * __ORG__GICTrackingID should always be UPPER, clean, 32-char — but when comparing against iMEP always guard with UPPER(TRIM(...))
 * SEG5 (channel) diverges: iMEP carries EMI/NLI/TWE, SharePoint IAN/ITS/OPN/ANC — '''ignore SEG5''' for cross-channel matching (see Rule 3 in StrategyContract)

!3 1:1 URL ↔ TID

Dies confirms: each URL has at most one TID, each TID at most one URL. '''URL-based aggregation''' is equivalent to TID-based — use URL as a fallback key if needed.

'''Refresh anomaly''': the entire table is overwritten once a day. MERGE on (id: PageUId). Page deletions propagate within at most 24h.
